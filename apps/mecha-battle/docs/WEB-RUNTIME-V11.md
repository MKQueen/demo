# 网页运行时升级 · 2026-10-24

当前开发主线恢复为网页：先打磨体感、战斗和表现，再迁移桌面引擎。保留 Unity 原生工程，本轮没有继续迁移或安装引擎。

## 四项落地

1. **后台推理**：`public/mediapipe/inference-worker.js` 使用本地 MediaPipe classic worker，在 OffscreenCanvas 上运行人物检测与裁剪后的骨骼推理。CPU delegate 避免依赖 worker GPU delegate 兼容性；部分 MediaPipe 内部图像转换仍可能创建 WebGL 上下文。主线程保留摄像头采样、轻量人物关联、校准、手势和叠画。一次只允许一帧在途，无帧队列；采集时间超过 500ms 的结果丢弃，重锁/断流用代次阻止旧结果重新接管。初始化 60 秒、单次推理 3 秒超时会终止 worker 并报错，可重新接入。缺少后台 API 时提示换浏览器或使用键盘，不悄悄退回主线程推理。
2. **固定战斗步长**：`src/runtime/fixedStep.js` 在渲染帧之间累计 1/60 秒模拟步，每帧最多补 5 步，长卡顿舍弃超额时间；页面隐藏暂停并清空输入和残余累积。战斗执行顺序移到 `src/combat/battleStep.js`，镜头、HUD、锁定指示和飘字走每帧 `Game.present()`。离散输入队列只在模拟步消费。固定 60 Hz 指模拟频率，不保证渲染达到 60 FPS；当前没有角色渲染插值，也未把所有菜单/动画更新拆成独立子系统。
3. **技能阶段表现**：`skillTimeline.js` 用动作实例与时间标记去重；`skillPresentation.js` 负责聚能、释放、收招。等离子在 .32 秒释放并撤掉聚能环，.6 秒散热；导弹按 .24/.315/.39/.465 秒逐枚反馈；光刃释放闪光，吐息口部聚能与释放、重踏/喷发地面压力波。聚能环朝向目标，粒子以固定节流预算汇聚到手/口。减少输入瞬间抢先的大闪光及等离子命中漫画星爆，保留既有喷气、武器扫掠和真实接触命中。表现标记不直接结算伤害。
4. **Rapier 碎块物理**：`debrisPhysics.js` 为现有实例化碎块提供重力、旋转、摩擦、碰撞及 CCD；上限 96 个动态碎块、48 个附近高楼盒体与地面。碎块生命结束、复用、重开和场景销毁会释放刚体；建筑标记倒塌后立即移除碰撞盒。建筑整体仍用原有坍塌动画，未实现任意切割、承重结构或碎块伤害；角色与近战继续使用骨骼扫掠判定。

`npm run dev` / `npm run build` 会从已安装的固定版本 MediaPipe 同步 classic bundle 到 public。新增 Rapier compat WASM 会增加首次加载体积，目前总构建 JS 约 5.3 MB（压缩约 1.9 MB），尚需继续优化资源加载与低配表现。

## 验证

- `npm test`：33 项通过，新增固定步长跨 30/60/144 渲染频率、卡顿限额、阶段去重、推理请求超时/取消/背压、碎块落地与高楼碰撞/倒塌移除等测试。
- `npm run build`：生产构建通过；`scripts/web-production-smoke.js` 验证预览端口 5191 的本地 worker 模型加载和实际 RAF 战斗更新，无未捕获异常。结构化记录见 `output/research/web-runtime-v11.json`。
- `scripts/worker-inference-smoke.js`：Playwright CLI 中用公开 MediaPipe 人物图片运行真实 worker 检测、锁定和骨骼推理；7 帧从 acquiring 到 tracked，随后 5 帧各返回 33 点。测试期间主线程定时器继续运行；这只是链路可用性检查，不是帧率或端到端延迟基准。
- `scripts/flight-combat-smoke.js`：喷气燃料、悬飞转向、空中受伤、避震、危险区域、双爪两段、举盾破防、技能发射/收招与重开通过；固定站桩玩家在自动推进场景中约 9.78 秒败北，不能代表难度平衡已完成。
- `scripts/pacific-combat-smoke.js`：骨骼运动、三连击、缓存/取消、防御、AI 追击与命中、倒地、胜负和重开通过。
- `scripts/web-runtime-smoke.js`：实际场景聚能/释放/散热阶段、建筑碎块刚体、预算和重开清理检查；截图 `output/playwright/web-runtime-v11.png`。

没有打开实体摄像头，没有测真人识别率、多人交叉、真实疲劳、Win/Mac 多设备帧率或摄像头到画面的总延迟。以上是网页版底层与局部表现升级，尚不构成正式发行验收。下一步应在真实体感试玩中记录误触、丢失恢复、延迟与帧耗时，再调整动作阈值、Boss 节奏和整体特效。
