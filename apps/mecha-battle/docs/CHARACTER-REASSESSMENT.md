# 角色表现重新评估

> 此文件记录 v10 之前的诊断基线。后续已落实的角色姿态、动作源工程、步态与攻击修正见 [CHARACTER-V10.md](CHARACTER-V10.md)；尾链、下颌及完整攻击重制仍待完成。

结论：当前是有较完整控制、碰撞、技能和城市破坏的战斗 Demo，角色表现未达到成熟动作游戏的质量。此轮只做诊断与升级路线，不把评估当作已经完成的动作重制。

## 实机与代码证据

2026-10-23 重新进入游戏，从正面、侧面检查待机姿态，并读取运行中的骨骼数据。

- 机甲默认 clip 为 guard。`src/world/importedCharacters.js` 的 selectClip 在无动作、无移动时返回 guard，防御和普通待机没有区别。
- guard 在 `src/world/combatAnimations.js` 里是一段静态手臂姿势，没有独立的骨盆、膝盖、脚掌承重设计。多数攻击从这段抱拳姿势开始并回到它。
- 怪兽 beast_idle 主要修改手臂。实机局部坐标中，骨盆 z=5.48、胸部 z=5.60、头部 z=5.65，身体主轴基本直立。该数字只是当前待机姿态的证据，不是所有怪兽必须遵守的美术比例标准。
- 怪兽 beast_walk / beast_run 直接复制下载的 walk / run，再覆盖手臂轨道，腿部仍沿用通用人形步态。
- 速度匹配分支只接受 walk / run，未覆盖 beast_walk / beast_run。怪兽移动速度与动画播放速度不能正确匹配，存在滑步根因。
- 两个资产都采用同名的 41 骨人形骨架，没有独立的尾巴骨链、下颌骨。怪兽表面有尾巴和嘴部外观，不代表能自然表演甩尾、张嘴咆哮或吐息。
- tail 行为选择 beast_slam，再旋转整个 holder。它不是真正由尾根到尾尖传递的尾扫动作。
- 自定义动作烘焙只输出骨骼旋转，没有输出骨盆位置轨道。文字注释里提到的下蹲、低重心没有完整落实到姿态。
- 当前贴地逻辑把最低一只脚对齐地面，不能保证另一只脚承重、双脚姿势合理，也不能代替完整的落脚与重心转移。

## 升级顺序

### 第一阶段：让角色单独站在空地上也成立

机甲建立独立的普通待机、战斗待机、格挡。战斗待机采用前后错脚、适度屈膝、稳定骨盆，手臂离开胸口；关节停稳与加减速体现机械重量。肩部和腰部保留受限活动范围，避免所有关节同时柔软摆动。

怪兽先确定一种身体语言：低重心、头颈探前、肩部主导、前爪下垂的双足重兽。站姿、移动、转身、攻击必须共用这个基准，避免待机像恐龙而出拳突然恢复拳击手。当前骨架可以试做低姿态和屈膝，但尾链、下颌及明显不同的腿部结构需要合适的资产或重新绑定。

资源验收先于接入：怪兽应带有尾链、下颌、可用蒙皮和兽类待机/行走/转身/攻击动画；机甲要检查肩甲穿插、膝踝弯曲和拳头姿态。公开可下载、外观像电影角色、能自动套人形动作，都不等于适合使用。优先清晰许可、实际带动画的免费资源。

第一阶段验收：关掉特效和 HUD，固定正面与侧面镜头，连续看十秒待机。能区分机械与生物，脚底稳定，肘膝方向正确，装甲与肢体没有明显穿插。不合格就继续修角色，不继续堆技能和地图。

### 第二阶段：移动与重心

机甲重踏、启动、刹停、侧移、原地转身；怪兽沉重步态、侧绕、扑进与止步。移动速度匹配步长和播放速度，落脚期固定支撑脚，转身采用脚步与髋部带动，而不是整个人像转盘一样旋转。分别录制低速/高速、起步/停步和左右转身验收。

### 第三阶段：只打磨少量完整攻击

机甲先完成一记重拳、一次刀斩、一次推进攻击；怪兽先完成爪扫、肩撞、张口吐息。每个动作完整覆盖预备、发力、接触、余势与复位，打中、打空、被打断均可衔接。保持已有实际接触判定，但在动作验收后重新校准窗口。尾扫在尾部资源合格后再做。

### 第四阶段：完整战斗小关卡

在一个街区内组织接近、压制、换位、破坏障碍、失衡追击和阶段切换；技能要有不同用途。难度依靠逼位、出招组合与清晰的反制机会，避免只缩短冷却、加血加伤。之后再扩展独立机甲、地图与模式。

## 本轮判断

前两轮环境和接触判定的工作可以保留，但下一轮最高优先级应转到角色资源与完整动作链。不能用更多特效、贴图或通过数值测试，作为角色表现达到正式版的证据。
