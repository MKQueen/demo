# 第 0 章：Agent 到底是什么

> **本章目标**：在写一行代码之前，先在脑子里建立一个准确的模型。
> 读完你应该能用自己的话回答：为什么"聊天机器人"不是 Agent？Agent 里到底哪部分在"思考"？
>
> 预计：25 分钟。

---

## 0.1 先接受一个残酷事实：大模型只会"接下一个字"

不管你听到多少"AI 会思考了"的说法，从工程角度看，大语言模型（LLM）就是一个函数：

```
输入：一段文本（messages）
输出：下一个 token 的概率分布
```

它做的全部事情，是根据你给的文本，猜最可能的下一个 token（词元），然后把这个 token 接到后面，再猜下一个。所谓"回答"，就是几百上千次"接龙"的结果。

这个事实推导出三个非常重要的结论：

**第一，模型没有记忆。**
你每次调用它，它都不记得上一次调用。所谓"多轮对话"，是你每次把**全部历史**重新发给它。你以为它在"记住"，其实是你在"重放"。

**第二，模型没有手。**
它不能读文件、不能执行命令、不能上网。它唯一能做的输出是文本。如果它说"我已经帮你删除了文件"，那只是它生成了这串字符，文件还在。

**第三，模型不知道现在几点。**
训练数据有截止时间，它不知道今天的日期、你的目录结构、你刚写的代码。它只能猜，猜就是幻觉（hallucination）。

> 💡 这三个事实是理解 Agent 的地基：
> **没有记忆 → 需要上下文管理；没有手 → 需要工具；不知道现实 → 需要把现实喂给它。**

---

## 0.2 Agent = 模型 + 工具 + 循环 + 上下文

先看一个公式，整本书都在解释它：

```
Agent = LLM（大脑） + Tools（手） + Loop（心脏） + Context（记忆）
```

| 组成部分 | 在程序里是什么 | 解决的问题 |
| --- | --- | --- |
| LLM | 一次 HTTP 请求，调 `/chat/completions` | 生成"下一步该干什么" |
| Tools | 一堆有名字、有参数 schema 的函数 | 让"下一步"能真的发生 |
| Loop | 一个 `while` 循环 | 让多步任务能连续做下去 |
| Context | 消息数组 + 裁剪/压缩策略 | 让模型"记得"刚才发生了什么 |

**所谓"手搓一个 opencode"，就是把这四个东西用代码拼起来。** 没有神秘的算法，没有需要训练的模型，全是工程。

好消息是：这四样东西加起来，核心代码不到 500 行。
坏消息是：真正难的是每一处的**细节取舍**——工具怎么设计才不让模型用错、上下文什么时候压、权限怎么卡、错误怎么喂回去。这些细节就是本项目的全部内容。

## 0.3 一次完整的 Agent 回合长什么样

这是全书最重要的一张图。请盯着它看 30 秒：

```
你（用户）
  │  "把 src/main.ts 里的版本号改成 0.2.0"
  ▼
┌─────────────────────────────────────────────────────────┐
│  你的程序（Agent）                                        │
│                                                         │
│  1. 组装 messages = [system提示词, 历史..., 用户这句话]      │
│     + tools 定义（每个工具叫什么、要什么参数）                 │
│                                                         │
│  2. POST /chat/completions  ──────────────┐              │
│                                            ▼              │
│                                    ┌──────────────┐       │
│                                    │    模型       │       │
│                                    └──────────────┘       │
│  3. 收到流式回复：                                          │
│     "我先看一下文件"                                        │
│     + tool_call: read({"path":"src/main.ts"})  ← 注意！    │
│                                            │              │
│  4. 你的程序解析 JSON，检查权限，真正执行 read               │
│     得到文件内容                                           │
│                                                         │
│  5. 把结果包装成一条 role="tool" 的消息，追加到 messages     │
│                                                         │
│  6. 带着新历史**再调一次模型** ──────────────┐             │
│                                            ▼              │
│                                    模型看到文件内容         │
│                                    决定调用 edit(...)      │
│                                    ……（回到第 4 步）       │
│                                                         │
│  7. 直到模型某一轮不再请求工具，只输出文字：                  │
│     "改好了，版本号从 0.1.0 变成 0.2.0。"                   │
└─────────────────────────────────────────────────────────┘
  │
  ▼
你看到最终回答（中间的工具调用过程也会显示给你）
```

**请特别注意第 3 步那个箭头。** 模型说"我要调用 read 工具"，它并没有真的读文件——它只是输出了这段 JSON：

```json
{
  "tool_calls": [
    { "id": "call_1", "type": "function",
      "function": { "name": "read", "arguments": "{\"path\":\"src/main.ts\"}" } }
  ]
}
```

真正读文件的是**你的程序**。这是理解 Agent 安全性的关键：**所有"AI 操作电脑"的能力，都是你（开发者）亲手赋予的。** 你给了它 `bash` 工具，它才能跑命令；你不给，它就只能在文本里"想象"。

## 0.4 为什么必须是"循环"，不能一次规划完？

你可能会想：让模型一次性把整个计划写完，然后程序照着执行，不就行了？

不行，因为**模型在行动之前看不到行动的结果**。

举个例子，任务是"修复这个项目的测试失败"：

- 模型不知道测试为什么失败，必须先跑一次测试（`bash npm test`）
- 看到报错后，才知道要读哪个文件（`read`）
- 读到文件后，才知道哪一行写错了（`edit`）
- 改完后，还要再跑一次测试验证（`bash`）

每一步的输入都依赖上一步的输出。所以只能是"做一步 → 看结果 → 决定下一步"，这个模式在论文里叫 **ReAct**（Reasoning + Acting）：

```
思考（Reason） → 行动（Act） → 观察（Observe） → 再思考 → …
```

我们这个 `while` 循环，就是 ReAct 的工程实现。真实 opencode、Claude Code、Cursor Agent，本质都是这个循环，只是外围工程做得更厚。

## 0.5 为什么这类程序叫 "harness"（马具）

业界常把 opencode / Claude Code 这类程序叫 **agent harness**。

`harness` 的原意是"马具、挽具"——套在马身上，把马的力量导向正确的方向。

这个比喻非常准确：

- **模型是马**：力量很大（能写代码、能推理），但方向不受控、会受惊（幻觉）、不知道自己踩到哪
- **harness 是马具**：缰绳（权限）、马鞍（工具）、路标（系统提示词）、行车记录仪（会话日志）

**你手搓的每一行代码，都是在做马具。** 模型能力越强，马具越重要——因为一匹失控的壮马比一匹失控的小马危险得多。

这也是为什么本项目里"权限系统""路径边界""危险命令识别"这些看起来"不 AI"的代码占了很大篇幅：**它们才是 Agent 能安全落地的前提**。

## 0.6 真实 opencode 长什么样

你现在手搓的 `mini-opencode` 是一个教学版。真实的 [opencode](https://opencode.ai) 是一个相当完整的工程，我们把它的结构和我们的对应关系摆出来：

| 真实 opencode | mini-opencode（本项目） | 说明 |
| --- | --- | --- |
| TypeScript + Bun monorepo | Node 24 + 原生 TypeScript，零运行时依赖 | 我们刻意不用构建工具，让你看到全部源码 |
| TUI / CLI / SDK / server 多端 | CLI + 终端渲染器 + 网页可视化面板 | 多端架构是工程问题，不是 Agent 原理问题 |
| 内置工具：`bash` `edit` `write` `read` `grep` `glob` `lsp` `todowrite` `webfetch` `websearch` `skill` `task` `question` | `bash` `edit` `write` `read` `grep` `glob` `todowrite` `task` | 我们实现了最核心的几个；lsp/webfetch/skill 属于扩展 |
| 权限 `allow` / `ask` / `deny`，支持通配符 | 同样的三档决策 + 按工具类别默认 | 简化了配置层，保留了核心模型 |
| `AGENTS.md` 项目规则 | 同样支持 `AGENTS.md` | 见第 8 章 |
| `build` / `plan` 等内置 agent 模式 | `build` / `plan` 两种模式 | 见第 8 章 |
| 子 agent（`task` 工具） | `task` 工具 + `agent/subagent.ts` | 见第 10 章 |
| 会话存 SQLite，支持事件溯源 | 会话存 JSONL，追加写 | 见第 7 章 |
| 自动上下文压缩（auto-compact） | 裁剪 + LLM 摘要压缩 | 见第 6 章 |
| Provider 目录来自 models.dev，支持几十家 | OpenAI 兼容协议 + mock | 见第 1 章 |
| MCP / LSP / 插件 / 分享 | 只讲概念，留作练习 | 见第 10、11 章 |

> 📌 想自己核对？官方工具文档在 <https://opencode.ai/docs/tools/>，
> 权限文档在 <https://opencode.ai/docs/permissions/>。

**我们的取舍**：砍掉所有"多端、多 provider、插件系统"的工程量，只保留 Agent 的骨架。这样你读 27 个文件就能看懂全貌，而不是在 monorepo 里迷路。

## 0.7 怎么用这套材料（学习路线）

本项目有两条并行的线：

**代码线**：`src/` 下的 27 个文件，按依赖顺序读：

```
llm/types.ts      数据结构（消息、工具、流事件）
llm/client.ts     和模型通信（手写 SSE 流式解析）
llm/mock.ts       假模型（没 key 也能跑）
tools/            工具：文件、bash、todo、cmd
agent/loop.ts     主循环（核心中的核心）
agent/context.ts  上下文管理
agent/prompt.ts   系统提示词
permission.ts     权限
session.ts        持久化
ui/               终端渲染
main.ts           总装
```

**文档线**：就是你现在读的 `docs/`，一章对应一个主题、一段代码。

**推荐的学习节奏**（每天 1 小时，约一周）：

| 天 | 读 | 跑 | 动手 |
| --- | --- | --- | --- |
| Day 1 | 第 0、1 章 | `npm run web`（勾选 mock） | 在网页里看一次完整回合 |
| Day 2 | 第 2、3 章 | `node examples/02-one-tool.ts --mock` | 自己加一个 `get_time` 工具 |
| Day 3 | 第 4 章 | `node examples/03-mini-agent.ts` | 把 maxSteps 改成 1，看会怎样 |
| Day 4 | 第 5、6 章 | `npm run chat`（真模型） | 让它改一个文件，观察 edit 的 oldString |
| Day 5 | 第 7、8 章 | `--session` 恢复 | 写一个自己的 AGENTS.md 规则 |
| Day 6 | 第 9 章 | `--yolo` / 权限审批 | 故意让它跑危险命令，看权限怎么拦 |
| Day 7 | 第 10、11 章 | `task` 子 Agent | 对照真实 opencode 源码结构 |

**"手搓"的正确姿势**：
1. 先读这一章，**合上书**，用白纸写出这一节的数据流（画箭头）
2. 自己写一个能跑的最小版本（哪怕 30 行）
3. 再看项目里的实现，对比差异 —— 差异处就是你要学的东西
4. 跑测试（`npm test`），改坏一处，看哪个测试会红

> ⚠️ 别一上来就通读全部源码。人类不是这么学代码的。
> 先跑起来，再按需读，带着问题读。

## 0.8 本章小结

- LLM 只是一个"文本进、文本出"的函数：没有记忆、没有手、不知道现实。
- Agent 补上了这三样：**上下文**（记忆）、**工具**（手）、**循环**（连续行动）。
- 模型永远不执行任何东西，它只生成"我想调用 xx 工具"的 JSON；**执行的是你的代码**。
- 这个循环叫 ReAct：思考 → 行动 → 观察 → 再思考。
- 这类程序叫 harness（马具）：你的代码就是缰绳和马鞍，决定了这匹马能跑多快、会不会踩人。
- 真实 opencode 和我们这个 mini 版，骨架完全一致，差的是工程厚度。
