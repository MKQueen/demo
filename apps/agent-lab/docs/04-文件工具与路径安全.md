# 第 4 章：文件工具与路径安全

> **本章目标**：搞清楚三件事——为什么编码 Agent 要有专门的文件工具、模型给错参数时程序怎么让它自己改、以及怎么保证它只能在你的项目里动手。
> 读完你应该能解释：`resolveInside` 为什么要沿路径向上找祖先再做 realpath、`edit` 为什么不用行号、`read` 为什么打印行号。
>
> 预计：35 分钟。

---

## 4.1 先建立直觉：别把万能钥匙直接塞给陌生人

让一个没进过你房间的人帮你整理书架，有两种给法：

- **给一把万能钥匙（bash）**，说"屋里的工具随便用"。他能干任何事，但你不知道他开了哪个抽屉，也不知道他会不会顺手打开保险柜。
- **给一套贴好标签的操作**：看第几层第几本、把这段文字换成那段文字、找标题带"算法"的书。格式固定，做完还能汇报结果。

bash 就是那把万能钥匙。它当然能读文件、改文件、搜索，但对**模型**有三个硬伤：输出不结构化（`cat` 不告诉你总行数，`sed -i` 不给 diff）；行为不可预测（引号、空格、通配符、平台差异都能让命令古怪地失败）；没有安全边界（`../../etc/passwd` 随便读，`rm` 随便删）。

所以编码 Agent 几乎都有一套专门的**文件工具（file tools）**：把"操作文件"拆成 `read`（看）、`write`（整写）、`edit`（局部改）、`glob` / `grep`（找），每个动作有明确参数、输出格式和边界。本章源码：`src/tools/types.ts`、`src/tools/registry.ts`、`src/tools/files.ts`。

## 4.2 核心概念逐条拆

### 概念 1：工具 = 名字 + 描述 + JSON Schema + 执行函数

大模型不认识 TypeScript 函数，只认文本。所以你要把工具的"接口"翻译成它能读的说明书（`description` + `parameters`），再把它"想调用"的 JSON 翻译回函数调用。所谓 function calling（函数调用），就是这套文本 ↔ 代码的翻译协议。

```ts
export interface Tool {                    // （字段合并排版，仅为省篇幅）
  name: string; description: string; parameters: JSONSchema;
  category: ToolCategory;
  execute(args: Record<string, unknown>, ctx: ToolContext): Promise<ToolResult>;
}
```

`parameters` 是一段 **JSON Schema**（用 JSON 描述"参数长什么样"）：类型、必填项、范围、枚举。`category` 是 `read` / `write` / `exec` 三档，给第 5 章的权限系统用。

### 概念 2：参数校验不是防御性编程，是自我纠错机制

模型生成的参数是一个 **JSON 字符串**，程序要 `JSON.parse` 再按 schema 校验。它错得很有规律：少引号、多逗号、参数名写成 `file_path`、`limit` 给字符串、漏必填。直接执行轻则报怪错，重则程序崩溃。

**关键在错误怎么回**：只回一句 `invalid arguments`，模型只能瞎猜；回"缺少必填参数 `path`"，它下一轮就知道补什么。这就是 Agent 的"自我纠错"闭环——不是模型变聪明了，是你把错误写清楚了。`registry.ts` 里 `validateArgs` 手写了约 100 行 JSON Schema 子集校验器，其中 `additionalProperties: false` 最值钱：挡住"模型自创参数名"，并顺便告诉它正确名字。

### 概念 3：`read` 的每个设计都在替模型省事

- **行号**：输出 `12| const a = 1;`，改代码时能引用行号；行号按总行数定宽右对齐。
- **offset / limit 分段**：大文件分段读；offset 超出可读范围会**明确报错**（而不是悄悄读最后一行）；读完直接告诉你下一次怎么调：`继续读：offset=47`。
- **大文件截断**：`MAX_READ_BYTES = 512 * 1024`，超了只读开头，并明确说"没读全"——别让模型误以为看了全部。
- **二进制 / 敏感文件拒绝**：前 8000 字节有 `0x00` 就拒读（`isBinary`）；`.env`、`id_rsa`、`*.pem` 等按文件名拦截（`isSensitiveFile`）。
- **错误也带下一步**：不存在 → "用 glob 找"；是目录 → "用 glob 或 bash ls"。

### 概念 4：`write` 与 `edit`，以及为什么 edit 用"精确字符串替换"

`write` 是整文件覆盖 + 自动建目录（`fs.mkdirSync(..., { recursive: true })`），返回"已创建/已覆盖 + 行数 + 字节数"，定位是**新建文件**；改已有文件优先 `edit`，否则会把模型没读过的内容一起冲掉。

`edit` 的接口是 `oldString` / `newString`，不是行号 patch。原因：**行号会漂移**（模型读完到修改之间，任何改动都让行号全错，补丁打歪比不打更糟）；**patch 格式对模型不友好**（要算上下文行、hunk 头，容易错还难定位）；**精确字符串替换恰好就是模型看得见的东西**——它读过文件就能复制原文，物理上不会波及其他行。

代价是必须唯一匹配，于是有三道闸门：`oldString === newString` 拒绝；找到 0 处报错并提示"缩进/空格不一致，先用 read 重读"；找到多处且没开 `replaceAll` 拒绝，要求更长上下文或 `replaceAll=true`。那句报错本身就是操作指南，模型下一轮大概率真去重读。

### 概念 5：`glob` / `grep` 是"找"，不是"看"

`walkFiles` 递归列文件，跳过 `IGNORED_DIRS`（`node_modules`、`.git`、`.mini-opencode`……）和**符号链接**（链接的 `entry.isFile()` 是 false），天然防止遍历出项目，最多 `MAX_WALK_FILES = 8000` 个。`globToRegExp` 把 glob 编成正则：`*` → `[^/]*`（不跨目录），`**/` → `(?:.*/)?`（零层或多层目录），`?` → `[^/]`，正则元字符转义。`grep` 用**正则**逐行匹配，输出 `文件:行号: 内容`，单行超 240 字符中间截断，跳过二进制/敏感/超大文件（2MB）。结果都有上限（glob 200 条、grep 100 条），并告诉你"共多少、只显示多少"。

### 概念 6：路径安全 = 折叠 .. + 沿路径向上找祖先

`resolveInside(cwd, input)` 是文件工具的第一道门：先 `realpathSync(cwd)` 得到真实根目录；`path.resolve(root, input)` 把 `../..` 折叠掉；再用 `path.relative` 判断是否越界（**不能用 `startsWith`**，`/a/bc` 也以 `/a/b` 开头）。接着沿目标路径**向上找到第一个真实存在的祖先**，对它 `realpathSync` 后再判一次——这是防**符号链接逃逸（symlink escape）**：项目里放个 `link -> /etc`，字面路径在项目内，真实目标在项目外；而 `link/new.txt` 这种"目标文件还不存在"的情况，只检查目标本身会漏掉，所以必须检查祖先。

### 概念 7：为什么每个 Agent 工具都必须自带上限

```ts
const MAX_READ_BYTES = 512 * 1024;      const MAX_READ_LINES = 2000;
const MAX_WALK_FILES = 8000;            const MAX_GLOB_RESULTS = 200;
const MAX_GREP_MATCHES = 100;           const MAX_GREP_FILE_BYTES = 2 * 1024 * 1024;
```

（实际代码每行一个 `const`，这里并排显示）因为**工具输出会原样进入对话历史**：直接烧 token、烧钱、挤掉有用信息。成本由调用方承担，所以上限必须工具自带，不能指望模型"自觉少读"。这是第 6 章的伏笔。

## 4.3 代码导览

### 4.3.1 路径边界：`resolveInside` 沿路径找祖先

```ts
export function resolveInside(cwd: string, input: string): string {
  const root = fs.realpathSync(cwd);
  if (!input) throw new Error("path 不能为空");

  const resolved = path.resolve(root, input);
  assertInside(root, resolved, input);

  // 从目标往上找，直到找到一个已存在的路径（文件或目录），
  // 取它的真实路径再检查一次是否仍在 root 内。
  let probe = resolved;
  for (;;) {
    if (fs.existsSync(probe)) {
      assertInside(root, fs.realpathSync(probe), input);
      break;
    }
    const parent = path.dirname(probe);
    if (parent === probe) break; // 已经到文件系统根了，理论上到不了这里
    probe = parent;
  }
  return resolved;
}

function assertInside(root: string, target: string, original: string): void {
  const rel = path.relative(root, target);
  if (rel.startsWith("..") || path.isAbsolute(rel)) {
    throw new Error(
      `路径越界："${original}" 解析后跑到了工作目录之外（${target}）。` +
        `Agent 只能操作 ${root} 里的文件。`,
    );
  }
}
```

`root` 自己也做 realpath，否则拿"符号链接形式的 cwd"跟"真实路径"比，永远会算出越界。`probe` 循环是防逃逸的关键：`link/new.txt` 不存在时，向上退到 `link`（存在），对它的 realpath 得到项目外的真实目录，`assertInside` 就能拦住；`parent === probe` 是"已经退到 `/`"的退出条件。报错里同时给原始路径和解析后的路径，模型能看懂自己怎么跑出去的。

### 4.3.2 macOS 符号链接坑：`toRel`

```ts
function toRel(cwd: string, file: string): string {
  const root = fs.existsSync(cwd) ? fs.realpathSync(cwd) : cwd;
  const rel = path.relative(root, file);
  return (rel || ".").split(path.sep).join("/");
}
```

macOS 上 `/tmp` 其实是 `/private/tmp` 的符号链接，`/var` 其实是 `/private/var`。`walkFiles` 给出的文件是 `/private/tmp/x/a.txt`；若 `toRel` 还用原始 `/tmp/x` 算相对路径，会得到一串 `../../private/tmp/...`，glob 就匹配不上。**一边 realpath 一边不 realpath，是路径 bug 的经典来源**——写测试时真踩过。

### 4.3.3 `read` 的行号与收尾提示

```ts
const safeOffset = Math.max(1, offset); // offset 已在上面做过范围检查
const numbered = slice
  .map((line, index) => {
    const lineNo = String(safeOffset + index).padStart(width, " ");
    return `${lineNo}| ${line}`;
  })
  .join("\n");
const end = safeOffset - 1 + slice.length;
const more =
  end < totalLines
    ? `\n\n（文件共 ${totalLines} 行，这里显示 ${safeOffset}-${end} 行。继续读：offset=${end + 1}）`
    : "";

return { title: `read ${rel}`, output: numbered + more + note };
```

`width` 是总行数位数，用来对齐；`more` 只在没读完时出现，且把下一次调用的参数算好；`note` 是超大文件截断说明。模型一眼就知道"看到了哪、还差多少、下一步传什么"。

### 4.3.4 `edit` 的闸门与替换

```ts
const before = fs.readFileSync(target, "utf8");
const occurrences = before.split(oldString).length - 1;

if (occurrences === 0) {
  // 完整报错见源码：列出两种常见原因，并提示"先用 read 重读"
  return errorResult(`edit ${rel}`, `在 ${rel} 里找不到要替换的原文。\n常见原因：…\n解决：…`);
}
if (occurrences > 1 && !replaceAll) {
  return errorResult(`edit ${rel}`, `oldString 在 ${rel} 里匹配到 ${occurrences} 处，不唯一。\n` +
    "解决：提供更长的上下文让匹配唯一，或者设置 replaceAll=true。");
}

const after = replaceAll
  ? before.split(oldString).join(newString)
  : before.replace(oldString, newString);
```

用 `split(...).length - 1` 数出现次数，免去正则转义；`replaceAll` 用 `split/join` 最稳。边界情况：这里没有文件版本号校验，如果别的进程同时改了文件，后写的会覆盖先写的。

### 4.3.5 `globToRegExp` 的核心分支

```ts
if (normalized[i + 1] === "*") {
  i += 2;
  if (normalized[i] === "/") { out += "(?:.*/)?"; i++; } // **/ 匹配 0 层或多层目录
  else out += ".*";
} else { out += "[^/]*"; i++; }                           // * 不跨目录
// 其余分支：? → [^/]，正则元字符加反斜杠，首尾拼 ^ 和 $
```

`[^/]*` 不跨目录，所以 `*.ts` 对 `src/a.ts` 是 false。但工具里加了一层兜底：**模式不含 `/` 时额外按文件名匹配一次**，所以实际搜 `*.ts` 能命中所有子目录——和 shell 直觉不同，是两害相权的取舍。

## 4.4 动手实验

以下命令都在 `mini-opencode` 目录执行。

**实验 1：read 分段 / 越界 / 敏感文件**

```bash
node --input-type=module <<'EOF'
import { readTool } from "./src/tools/files.ts";
const ctx = { cwd: process.cwd(), signal: new AbortController().signal, state: {} };
console.log((await readTool.execute({ path: "src/config.ts", offset: 39, limit: 8 }, ctx)).output);
console.log("--- 路径越界 ---");
console.log((await readTool.execute({ path: "../../../etc/passwd" }, ctx)).output);
console.log("--- 敏感文件 ---");
console.log((await readTool.execute({ path: ".env" }, ctx)).output);
EOF
```

预期输出（你的绝对路径会不一样）：

```
 39| const DEFAULTS = {
 …（中间省略）
 46| 
（文件共 123 行，这里显示 39-46 行。继续读：offset=47）   # ← 行号按 123 行定宽；下一页入口
--- 路径越界 ---
路径越界："../../../etc/passwd" 解析后跑到了工作目录之外（/Users/one/etc/passwd）。Agent 只能操作 /Users/one/Web/LearningDemo/mini-opencode 里的文件。
--- 敏感文件 ---
出于安全考虑，read 工具默认禁止读取可能包含密钥的文件（.env/.npmrc/*.pem 等）。如果确实需要，请让用户自己操作。
```

第二段显示的是 `path.resolve` 折叠 `../..` 之后的绝对路径——模型能看懂自己错在哪。

**实验 2：write / edit 在临时目录里真实读写**

```bash
node --input-type=module <<'EOF'
import fs from "node:fs";
import { editTool, writeTool } from "./src/tools/files.ts";
const cwd = fs.mkdtempSync("/tmp/mini-04-");
const ctx = { cwd, signal: new AbortController().signal, state: {} };
console.log((await writeTool.execute({ path: "src/hello.ts", content: "const a = 1;\nconsole.log(a);\n" }, ctx)).output);
console.log((await editTool.execute({ path: "src/hello.ts", oldString: "const a = 1;", newString: "const a = 42;" }, ctx)).output);
console.log((await editTool.execute({ path: "src/hello.ts", oldString: "const a = 2;", newString: "x" }, ctx)).output);
fs.rmSync(cwd, { recursive: true, force: true });
EOF
```

预期输出：

```
已创建 src/hello.ts（3 行，29 字节）
已修改 src/hello.ts（替换 1 处，行数变化 0）
在 src/hello.ts 里找不到要替换的原文。
常见原因：
  1. 缩进/空格不一致（务必逐字符复制）
  2. 文件已经被改过，内容变了
解决：先用 read 工具重新读一遍文件，确认原文后再 edit。
```

**实验 3：用测试当行为说明书**：`node --test test/tools.test.ts`，预期结尾 `ℹ tests 24 / ℹ pass 24 / ℹ fail 0`（含五条符号链接回归测试：目录链接、悬空链接、写逃逸、路径检查、别名路径允许）。每个 `test(...)` 名字就是一条约定（越界被拒、`.env` 被拒、edit 多处匹配被拒），改代码前读测试比读文档快。

## 4.5 常见坑

**坑 1：把 `read` 输出的行号前缀复制进 `oldString`**
- 症状：`edit` 报"找不到原文"，但肉眼看一模一样。
- 原因：`12| ` 是展示用的行号，不在文件里。
- 避免：只复制 `| ` 右边的内容；不确定就重新 `read`。

**坑 2：macOS 上 `/tmp/...` 和 `/private/tmp/...` 混着比**
- 症状：自己写的路径判断在 macOS 上莫名错位，glob 对不上。
- 原因：`/tmp`、`/var` 是符号链接，`process.cwd()` 常常返回 `/private/...`。
- 避免：比较前统一 `realpathSync`（`toRel` 就是这么干的）。

**坑 3：把敏感文件保护当"密钥安全"**
- 症状：`read .env` 被拦，但 `config/prod-secret.txt` 照样读。
- 原因：`isSensitiveFile` 只按文件名匹配几个模式，不是内容扫描器。
- 避免：别把密钥放进工作目录；真正的隔离是第 5 章的权限 + 沙箱/容器。

**坑 4：以为符号链接检查天衣无缝（写文档时实测发现的 bug，现已修复）**
- 症状（旧实现）：项目里有指向工作目录外的目录链接时，**新建**文件会被写到外面（写完 `read` 反而报越界）。
- 原因：旧代码只在 `fs.existsSync(resolved)` 为真时做 realpath，而 `write` 的目标文件往往还不存在，检查被整段跳过。
- 修复：`resolveInside` 改为从目标向上找**第一个存在的祖先**，对它 realpath 后再判断；新增两个回归测试——`resolveInside: 拒绝通过符号链接目录逃逸（即使目标文件还不存在）` 和 `write: 不会通过符号链接把文件写到工作目录外`（都在 `test/tools.test.ts`）。
- 教学点：这是写本章实验时实测发现的——**写文档、跑测试、审阅别人的代码，都能发现安全 bug**；修完补回归测试，比"修了就算"重要得多。

## 4.6 本章小结

- 文件工具不是 bash 的封装，而是为了**结构化输出、可预测行为、安全边界**。
- 工具 = 名字 + 描述 + JSON Schema + 执行函数；`additionalProperties: false` 能挡住模型自创参数。
- 参数校验失败要把**具体错误**喂回模型，这是自我纠错能力的来源。
- `read` 用行号、分段、续读提示、二进制/敏感文件拦截，替模型省脑子。
- `edit` 用精确字符串替换而非行号 patch；行号会漂移，代价是必须唯一匹配。
- 路径安全靠 `resolveInside`：`path.resolve` 折叠 `..`、`path.relative` 判越界、沿路径向上找第一个存在的祖先再 realpath 防符号链接逃逸。
- 所有文件工具都自带上限——工具输出最终会变成上下文 token，这是第 6 章的伏笔。

## 4.7 练习

1. **给 `glob` 加 `maxResults` 参数**：改 schema（`minimum`、`maximum`）和 `execute`（替换硬编码的 `MAX_GLOB_RESULTS`，保留"只显示前 N 个"的提示）。提示：先跑 `node --test test/tools.test.ts`，确认没破坏现有测试。
2. **给 `read` 加"读完后提示 token 估算"**：用 `src/util.ts` 的 `estimateTokens` 算正文，超 3000 时在末尾加警告。提示：想想该放进 `note` 还是 `more`；`note` 的语义是"这次读取有损"。
3. **体验回归测试的价值**：临时把 `resolveInside` 改回旧实现（只检查"目标自身是否存在"、跳过祖先检查），跑 `node --test test/tools.test.ts`，看哪两个测试变红，再改回来。提示：也可以继续探索其它逃逸向量——`mkdirSync` 递归创建时穿过软链接、Windows 的 junction；想想"目标父目录已存在"和"目标父目录也不存在"为什么要分开处理。
