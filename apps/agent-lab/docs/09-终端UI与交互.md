# 第 9 章：终端 UI 与交互

> **本章目标**：把 Agent 的"脸"和"手"补齐。读完后你能解释：流式输出为什么不能等完整回复？
> `\r\x1b[2K` 这一串鬼画符在干什么？Ctrl+C 为什么有两种含义，AbortController 是怎么贯穿
> 到 `fetch` 的？为什么管道/CI 里跑 Agent 权限会全部被拒？
>
> 预计：25 分钟。对应代码：`src/ui/ansi.ts`、`src/ui/renderer.ts`、`src/ui/input.ts`、`src/main.ts` 的 REPL 与信号处理。

## 9.1 先建立直觉：主刀医生和护士

Agent 的主循环像一位话很多的外科医生：他专心做手术（推理、调工具），但每隔一会儿要报一句"我现在切到第几层"。如果让他全程闭嘴、做完再一次性汇报，家属（用户）会在手术室外面干等三十秒，以为他死了。所以需要一位护士（UI 层）：把医生的进展**实时**翻译给家属，同时把家属的话（输入）、叫停（Ctrl+C）、授权（权限确认）传回给医生。护士不参与手术——她不该知道手术怎么做。

这就是本章的架构：**主循环管"发生了什么"，UI 管"怎么显示"**。真实 opencode 用 OpenTUI（SolidJS 渲染的终端 UI 框架）做完整 TUI：多行输入、历史、快捷键、模糊搜索；我们用 Node 自带的 `readline` + `process.stdout.write` 做最小版，但交互模型一样。

## 9.2 核心概念逐条拆

### 概念 1：流式渲染（streaming render）

模型回复是流式到达的：HTTP 响应是 SSE（Server-Sent Events），一个个 `data: {...}` 事件里带着 delta（增量文本）。主循环收到一块就立刻交给 UI 一块（`src/agent/loop.ts`）：

```ts
        switch (event.type) {
          case "text":    text += event.text; ui.assistantText(event.text); break;
          case "thinking": ui.assistantThinking(event.text); break; // 思考只显示，不进历史
          // …（tool_calls / usage / done 分支省略）
```

为什么不等完整回复再显示？一次 Agent 回复可能 10～30 秒，中间还要调工具。流式把首字延迟从 30 秒压到一秒内——这是现代 Agent 产品的底线体验，不是锦上添花。

### 概念 2：占位符与清行：`\r` + `\x1b[2K`

请求刚发出、第一个 token 还没到，屏幕上先显示 `● 思考中…`。第一个字到达时，用两个控制序列把它擦掉：

- `\r`：回车，把光标移到**行首**（不换行、不删内容）；
- `\x1b[2K`：ANSI 的"清除整行"，把这一行抹掉。

然后重写 `● ` 前缀，接着打印正文。终端的本质是"字符流 + 光标"，没有"修改已输出文字"的 API，只能用光标控制覆盖。少了 `\x1b[2K`、只靠 `\r`，新内容比旧内容短时就会留下"思考中…"的尾巴（残影）。非 TTY 环境里 `clearLine()` 退化为 `"\n"`——日志不需要光标控制。

### 概念 3：ANSI 颜色、TTY 检测与 NO_COLOR

终端上色就是往输出里塞转义序列：`\x1b[36m` 青色、`\x1b[0m` 重置、`\x1b[2m` 暗色。`src/ui/ansi.ts` 没有魔法也没有 chalk，就是一张码表加一个开关：

- 开关：`process.stdout.isTTY === true && !process.env.NO_COLOR`；
- 为什么强调 TTY：输出重定向到文件/管道时，加颜色等于往日志里塞乱码转义，`grep`、CI 日志、`docker logs` 都会很难看；
- `NO_COLOR`：社区约定（no-color.org）——只要这个环境变量存在且非空，就不要吐颜色，让用户能主动关掉。

`symbols` 里还定义了 `❯ ● → ✓ ✗ ! ·` 这些符号；纯 ASCII 环境可能显示成问号，这是本项目已知的小限制。

### 概念 4：工具行与输出截断

工具调用最该展示（用户要知道 Agent 干了什么），但不能刷屏：开始时 `→ bash {"command":"ls -la"}`，参数压成一行预览（`oneLine`，最多 120 字符）；结束时 `✓ bash · 15ms` 或 `✗ write · 2ms`，然后只显示输出前 12 行，剩下的提示 `…（还有 N 行，已省略）`。完整输出不会丢——它在会话文件的 `message` 行里（第 7 章）。UI 只负责让人看懂，细节请翻账本。

### 概念 5：readline 输入封装：line 事件 + 行队列

`src/ui/input.ts` 没有直接暴露 `rl.question()`，而是统一监听 readline 的 `line` 事件，再配一个**行队列**：有人在等（`ask()` 的 Promise 还没解决）就直接把行给他，没人等就入队。为什么？Agent 跑一轮要几秒到几十秒，这期间管道里的后续行（或用户手快多敲的行）会立刻到达；旧实现用 `question()` 时，没人接手的行会被静默丢掉——表现为"管道里第二条斜杠命令不生效"。

- **EOF（Ctrl+D / 输入流结束）**：`rl.on("close")` 把挂起的 `ask()` 用 `null` 解决，REPL 收到 `null` 就 `break`，打印"再见 👋"；
- **管道输入**：`terminal: process.stdin.isTTY === true`，非 TTY 时关掉终端编辑、按行喂入；`main.ts` 再补两处适配——不打印 `❯ ` 提示符、手动回显用户输入。

### 概念 6：Ctrl+C 的两种含义 + AbortController

同一个按键，两种含义：**生成中**＝中断当前回合，但保留已经生成的部分文本（用户可能只是不想等）；**空闲时**＝退出程序。`src/main.ts` 用一个 `process.on("SIGINT")` 处理器区分：`app.isGenerating` 为真就 `abortCurrentTurn()`，否则 `app.shutdown(0)`。

`abortCurrentTurn` 做的事是 `this.abortController.abort()`。这个 signal 一路传下去：`runAgent(..., signal)` → `provider.stream(..., { signal })` → `fetch(..., { signal })`——网络请求被真正取消，而不是把进程杀掉。`AbortController` 是**协作式取消**：每个耗时环节自己检查 signal 并主动退出，好处是循环有机会收尾——把已生成的部分文本写进历史、给没来得及执行的 tool_call 补一条"被中断"结果、记一条 `turn_end(aborted: true)`，然后干净返回。直接 `process.exit()` 则这些全丢。

（小细节：实测在交互式提示符上按 Ctrl+C，readline 可能先把这次按键解释成输入结束、走 EOF 分支打印"再见"；生成中则一定走 abort 分支。但生成中被中断的那一轮会被判定为"任务未完成"：`run` 模式的退出码因此是 1，而 `chat` 模式只是回到提示符。）

### 概念 7：交互式 vs 非交互式，以及 run 模式

`main.ts` 的判定只有一行：`const interactive = process.stdin.isTTY === true && options.command === "chat";`。它影响权限行为：

- 真实终端 `chat`：权限 `ask` 弹确认框，等 y/n/a；
- 管道/CI（非 TTY）：`ask` **直接拒绝**，错误信息提示加 `--yolo`；
- `run "任务"`：没有 Input 实例，同样直接拒绝。

`run` 一次性模式：任务描述来自命令行参数或管道 stdin（`readStdin`），跑完 `app.shutdown(ok ? 0 : 1)`。**退出码语义是"这一轮任务是否顺利完成"**——`runTurn` 只在 `!aborted && !hitStepLimit && toolDenials === 0` 时返回 true：正常完成 0；被 Ctrl+C 中断 / 达到 `--max-steps` / 有工具被权限拒绝 → 1；启动失败或循环抛异常也是 1。`chat` 模式不看这个返回值，所以交互式会话里权限被拒不会退出程序。

### 概念 8：AgentUI——UI 层不进主循环

主循环不 import 任何 `src/ui/` 里的东西，只依赖一个接口（`src/agent/loop.ts`）：

```ts
export interface AgentUI {
  assistantStart(): void;
  assistantText(delta: string): void;
  assistantThinking(delta: string): void;
  assistantEnd(): void;
  toolStart(name: string, argsPreview: string): void;
  toolEnd(result: ToolResult, durationMs: number): void;
  info(message: string): void;
  notice(message: string): void;
  error(message: string): void;
}
```

这个接口换来三样东西：**可测试**——`test/loop.test.ts` 里的 `silentUI` / `recordingUI` 让循环测试完全不碰终端；**可替换**——将来加 Web UI，主循环一行不改；**可复用**——`src/agent/subagent.ts` 直接给子 Agent 一个静默 UI，避免刷屏。记住原则：**UI 只消费事件，不参与决策**。

## 9.3 代码导览

### 9.3.1 流式输出的实现：renderer 的占位与擦除

```ts
  assistantStart(): void {
    process.stdout.write("\n");
    if (this.interactive) {
      // 先占位，等第一个字到了再擦掉
      this.pending = true;
      process.stdout.write(cyan(symbols.assistant) + " " + dim("思考中…"));
    } else {
      process.stdout.write(cyan(symbols.assistant) + " ");
    }
  }
```

`assistantStart` 只负责占位和状态位 `pending`。第一个 delta 到达时，`assistantText` 先 `clearLine()` 擦掉占位、重写 `● ` 前缀、把 `pending` 置 false，然后**逐块 `write`，绝不加换行**——加换行就不是流式了。`assistantThinking` 用同样的擦除逻辑，但正文用 `dim()` 上灰色，与正式回答区分；`assistantEnd` 收尾时若还在占位态会擦掉并补一个换行。

### 9.3.2 ANSI 工具：一个开关，一张码表

```ts
const enabled = process.stdout.isTTY === true && !process.env.NO_COLOR;

export const codes = { reset: "\x1b[0m", dim: "\x1b[2m", cyan: "\x1b[36m", /* …其余码 */ } as const;
export const cyan = (text: string) => paint(text, codes.cyan); // paint 在非 TTY 时原样返回
/** 清除当前行（用于“思考中…”变成正式输出）。非 TTY 时退化为换行。 */
export function clearLine(): string {
  return enabled ? "\r\x1b[2K" : "\n";
}
```

`paint(text, code)` 在 `enabled` 为 false 时原样返回文本，所以所有调用点都不用自己判断；`\x1b[0m` 必须成对出现，否则颜色会"漏"到后面所有输出。

### 9.3.3 输入封装：line 事件 + 行队列

```ts
    this.rl.on("line", (line) => {
      if (this.waiter) {
        const resolve = this.waiter;
        this.waiter = null;
        resolve(line);
      } else {
        this.queue.push(line);
      }
    });
    // …（close 事件省略：closed = true; waiter?.(null)，让 ask 返回 null）
```

`ask()` 的逻辑正好相反：先把队列里已经到达的行取走（`this.queue.shift()`），队列空且未关闭时再挂一个 `waiter`。这个行队列就是修复"管道多行被吞"的关键；`terminal: process.stdin.isTTY === true` 则决定 readline 要不要接管行编辑与回显。

### 9.3.4 Ctrl+C：分派与协作取消

```ts
  // Ctrl+C：运行中 = 中断当前回合；空闲 = 退出
  process.on("SIGINT", () => {
    if (app.isGenerating) {
      app.abortCurrentTurn();
    } else {
      app.shutdown(0);
    }
  });
```

`abortCurrentTurn` 只做三件事：判断有没有进行中的 `AbortController`、用 `renderer.notice` 提示"已中断（已生成内容会保留）"、调 `abortController.abort()`。`isGenerating` 是 `App` 的状态位：`runTurn` 一进来置 true，`finally` 置 false。SIGINT 处理器只做"分派"，真正的中断语义在 `abortCurrentTurn` 里。

### 9.3.5 主循环怎么处理 abort：保留半句话

```ts
    } catch (err) {
      ui.assistantEnd();
      // 用户中断：保留已经生成的部分文本，方便接着聊
      if (signal.aborted || isAbortError(err)) {
        if (text.trim()) {
          const partial: ChatMessage = {
            role: "assistant",
            content: text + "\n\n[本回合被用户中断]",
          };
          history.push(partial);
          options.session?.persistMessage(partial);
        }
        return { steps, usage, aborted: true, hitStepLimit: false, toolDenials };
      }
      throw err; // 其他错误（网络、鉴权、限流）抛给上层处理
    }
```

这就是协作取消的收益：取消后循环还能写会话、还能返回结构化的 `{ aborted: true }`。顺带一个协议细节：中断时若 assistant 已经声明了 N 个 tool_call，循环会给没来得及执行的调用各补一条"被中断"的 tool 结果，否则这份历史下次发给真实接口会 400。标记 `[本回合被用户中断]` 也很重要——下次恢复会话时，模型能看懂"这句话没说完"。

## 9.5 常见坑

| 坑 | 症状 | 原因 | 怎么避免 |
| --- | --- | --- | --- |
| 用 `console.log` 输出流式 delta | 每个字一行，或每行带时间戳 | `console.log` 自动加换行 | 流式必须 `process.stdout.write`，自己控制换行 |
| 管道/CI 输出里带颜色 | 日志里全是 `[36m` 之类乱码 | 没判断 `isTTY` | 上色判断 `process.stdout.isTTY && !NO_COLOR` |
| 只用一个 `\r` 清行 | 短内容覆盖长内容后留残影 | `\r` 只移动光标，不删字符 | 用 `\r\x1b[2K` 清整行；非 TTY 退化为换行 |
| 生成中直接 `process.exit()` | 已生成文本丢失、会话没有收尾记录 | 进程被强杀，循环没机会收尾 | 用 AbortController 协作取消，让循环自己保存后返回 |
| 把 UI 逻辑塞进主循环 | 循环没法单测，换 UI 要动核心代码 | 职责耦合 | 用 `AgentUI` 接口 + 测试替身（`silentUI`） |

## 9.6 本章小结

- 主循环管"发生了什么"，UI 管"怎么显示"；`AgentUI` 接口是它们之间唯一的契约。
- 流式渲染把首字延迟从几十秒压到一秒内；实现就是逐块 `process.stdout.write`，不加换行。
- 占位符 `● 思考中…` + `\r\x1b[2K` 清行，是纯文本终端里"擦掉重写"的唯一办法；非 TTY 退化为换行。
- ANSI 颜色 = 转义序列 + 一个 `isTTY && !NO_COLOR` 开关；管道输出必须无色。
- readline 用 `line` 事件 + 行队列收输入，避免管道多行被静默吞掉；`close` 事件把 EOF 转成 `null`，是程序能优雅退出的关键。
- Ctrl+C 双语义：生成中是 abort（保留半句话、写会话、返回 aborted），空闲时退出；AbortController 把取消信号一路传到 `fetch`。
- 退出码：`run` 正常完成 0；中断 / 达到步数上限 / 工具被权限拒绝 → 1（`chat` 不看返回值，权限被拒不退出程序）。
- 真实 opencode 用 OpenTUI/Solid 做完整 TUI；我们做最小渲染，但"UI 不进主循环"的设计是一样的。

## 9.7 练习

1. **做一个 spinner（转圈动画）**：等待第一个 token 之前，让 `思考中…` 后面的省略号循环，第一个 delta 到达时停止并清行。提示：`setInterval` + `clearLine()`；注意 `assistantEnd` 里一定要 `clearInterval`，否则进程退不出去。

2. **实现 `--json` 输出模式**：写一个 `JsonUI implements AgentUI`，把每个事件以 JSONL 打到 stdout（`{"type":"text","text":"…"}`），方便脚本消费。提示：参考 `test/loop.test.ts` 里的 `recordingUI`；想清楚工具结果要不要完整输出、非 TTY 下怎么保证纯 JSON。

3. **给 Ctrl+C 加"二次确认"**：第一次在空闲时按 Ctrl+C 显示"再按一次退出"，1 秒内再按才退出；生成中的语义不变（仍只中断当前回合）。提示：改 `main.ts` 的 SIGINT 处理器；用时间戳判断；想清楚第二次按的时候 `isGenerating` 可能是什么状态。
